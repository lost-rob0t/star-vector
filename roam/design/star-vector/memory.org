* Verified observations

The starting tree is merged =0247e40644d3277cf1c4f61337e449f278693688=.
Its worker decodes one Tek9 record, serializes the stored JSON string inside a
second JSON object, and Nim parses that envelope and then the record string.
The current top-k heap retains O(k) results. Prior 50k-row measurements show
roughly 30 MiB parent RSS and hundreds of MiB worker RSS; those measurements
combine anonymous allocations, code/core mappings and LMDB file pages.
No claim that all worker RSS is retained live data is supported yet.

* Plan and gates

First pin the merged source as a validation-only baseline. Build baseline and
candidate with the same Nim/SBCL/Tek9 dependencies and identical benchmark-only
instrumentation. Record RSS/PSS/anonymous memory and mapping classes separately,
SBCL cumulative allocation, sampled dynamic-space occupancy and callback
allocation, natural steady state and explicit full-GC live bytes. Instrumented
images are benchmark artifacts; the normal worker remains uninstrumented.

Use a shared synthetic 50k-row, 128-dimensional, 1 KiB document dataset, with
k=10, repeated searches, reopen, and multiple independent handles. Compare
latency/throughput as well as peak/steady memory. Sampling and forced-GC effects
must be labeled; mapped pages must not be reported as live heap or hidden from
total RSS. Select an implementation change only after observing the baseline.

Preserve producer import, read-snapshot consistency, exact ordering/ties,
CLI/C ABI/Lisp behavior, concurrency, crash recovery, migration checkpoints and
foreign-store/source preservation. Do not change user data, lower heap limits
as a substitute for reducing allocation, copy producer storage, or deploy.
Rerun native x86_64/aarch64 checks and request independent review before merge.
