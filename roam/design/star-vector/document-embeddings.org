* Observations

The current Nim library, C ABI, CLI and Common Lisp CFFI accept raw vectors.
No text provider exists in this repository or the inspected adjacent projects.
Tek9 remains the imported, authoritative producer. Its write transaction can
atomically enforce an optional immutable embedding profile in the existing
application header. Existing raw-vector stores and explicit migration remain.

Binding upgrades only an empty store's application header to format 2 and a
distinct ready-profiled state. The existing v1 producer adapter rejects both
fresh opens and writes from an already open handle, so older software cannot
silently mix raw vectors into the newly profiled store. Normal unbound stores
remain format 1. This is an application compatibility change, not a Tek9 fork.

The selected nixpkgs revision provides spaCy 3.8.16. The official English
en_core_web_md 3.8.0 wheel was retrieved from GitHub on 2026-10-11, SHA256
5e6329fe3fecedb1d1a02c3ea2172ee0fede6cea6e4aefb6a02d832dba78a310.
Hugging Face and Google Storage artifact attempts returned proxy HTTP 403.
This is a static English word-vector baseline, not a contextual transformer
or evidence of domain retrieval quality. Use the producer's tokenizer and
Doc.vector pooling API; do not recreate an encoder or storage implementation.

* Execution plan

Add an immutable, dimension-checked profile binding only for empty stores.
Enforce binding and compatible writes in the same Tek9 transaction. An old
raw handle must not write into a newly bound store. Preserve raw APIs for
unbound stores, and add profile-aware C/Nim calls. No adoption of populated
unbound stores, implicit reembedding, or legacy rewrite.

Implement a reusable Python library over that C ABI. Extract rawContent
verbatim, tokenize the complete accepted text, pool through spaCy Doc.vector,
normalize in float64 and persist float32. Pin provider version and model
artifact hashes; include dimensions, preprocessing, normalization and text
extraction version in the profile. Reject empty/zero-vector or over-limit
input explicitly. Preserve document ID, provenance and unrelated extensions;
attach text digest and profile metadata in a reserved extension.

Expose convenience commands through the existing CLI, with stdin support
for text/documents. Add Common Lisp, Nim and JS/TS convenience clients using
those commands, retaining existing native interfaces. Python supports an
in-process reusable encoder/store. No daemon, network protocol, paid API or
runtime model download. Package an optional text flake output with fixed
model assets, leaving the lightweight numeric package usable independently.

Validate synthetic deterministic profile/write/reopen/race/error behavior,
all four metrics, and cross-language update/search/readback. Separately run
the actual pinned model on synthetic prose, record exact versions, hashes,
timings and limitations, and include reopen and abrupt process termination.
Retain scale evidence and billion/history design without claiming new ANN
implementation or billion-scale execution.
