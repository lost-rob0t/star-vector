* Exact cosine optimization experiment gate

The baseline C ABI over 50k x 128 transient rows passed all 1000 query ID
oracles, with p50 30.35 ms and p95 33.74 ms. The 50k x 1536 cell passed
100 query oracles at p50 261.60 ms. These preliminary timings include some
overlapping setup work and are not the final paired performance claim.
Source inspection shows four vector reductions per cosine candidate:
zero-candidate norm, query norm, second candidate norm, and dot product.

Admit the narrow experiment: compute the unchanged float64 query norm once
per search and reuse the candidate norm computed for zero exclusion. Keep
each reduction order, division expression, error behavior, ID ties and
storage format unchanged. Retain only after independent numerical checks
and sequential matched baseline/candidate runs. No persisted norm cache or
ANN sidecar is introduced by this experiment.

* Measured acceptance of norm reuse

After the environment resumed, sequential process-isolated ABBA runs used
the same compiler, synthetic inputs and baseline/candidate shared libraries.
At 50k x 128, baseline medians were 29.693/28.110 ms and candidate medians
18.171/18.871 ms. At 50k x 1536 they were 248.388/256.504 ms and
148.759/142.314 ms. Each process checked 100 queries against the independent
oracle. IDs and serialized float64 score digests were identical across all
four passes at each dimension. The average of the two process medians fell
about 36% and 42%, respectively. These are transient C ABI measurements,
without the memory sampler, not evidence of a comparable persistent speedup.

The 10k x 128 persistent ABBA run also preserved all result digests, but its
five-query medians varied from 839 to 1376 ms. Candidate medians were about
1363/1369 ms. This experiment does not establish a persistent latency gain;
the producer/JSON/validation scan remains the dominant path. Retain the
small arithmetic optimization because of its measured transient benefit,
unchanged exact semantics and passing native integration checks, while
reporting the storage bottleneck without a production-readiness claim.

Native runs 38121343648 (4bd6ee6) and 38122424201 (57dead8) passed x86_64,
aarch64 and RAGE checks. Both architectures ran the new 400-check persisted
metric contract plus existing CLI/C ABI/Lisp, concurrency, crash and migration
checks. Final-head checks and independent review remain required before merge.
