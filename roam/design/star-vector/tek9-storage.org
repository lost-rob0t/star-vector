* Verified facts (2026-10-11)

Star Vector main 59e22b4 uses a Nim table and complete JSON replacement. Packaging
PR 4 at bc76fb3 provides installed CLI/C/Lisp checks. Its main merge b2cd4f4 was
incorporated into this feature branch; draft PR 6 now targets main.
Tek9 e6d1cb86a2e268a894eae3acae9617238b2adcff exports an ASDF library through
=packages.<system>.tek9=. Its public =put-bulk=, =fetch*=, =delete-document=,
=with-write-transaction= and =map-database= cover this adapter. =map-database=
decodes one entry at a time in one LMDB read transaction. Normal writes compose
with outer transactions; non-local exits abort. =:full= requests data and metadata
sync. LMDB serializes writers across processes. The map is fixed at 16 GiB by
default; there is no automatic growth. =put= tracks changed IDs in memory;
=put-bulk= without change tracking avoids that growth.

* Decision and adversarial review

Import the pinned library in a private SBCL worker per persistent handle, over
local pipes. No listening service, storage reimplementation, or copied Tek9
source. Existing producer exports suffice; no upstream patch is justified.
Keep schema validation and all metric arithmetic in Nim. Cursor results are
streamed into a bounded top-k heap with ID tie-breaking. One search holds a read
snapshot; slow readers pin LMDB pages. Worker startup, IPC, JSON and full record
decoding have costs that must be measured. Worker failure invalidates its handle;
never retry an ambiguous mutation automatically.

New paths are dedicated Tek9 directories. Empty-path transient stores retain
the memory backend. Existing JSON files are read-only through the legacy reader;
flush/close never rewrite them. Explicit migration validates the entire legacy
snapshot first, preserving its original bytes, then writes to a different path.
The legacy parser still uses memory proportional to the snapshot and is not an
archive-scale streaming importer. Source fingerprint, dimensions, count and
progress are transactional metadata. Each bounded batch and checkpoint commit together.
Incomplete destinations reject ordinary opens/mutations. Resume checks source
identity and progress; readback verifies every record before publication.
Competing migrators are fenced by expected progress. No automatic deletion or
overwrite of existing unrelated stores. Synthetic fixtures only.
