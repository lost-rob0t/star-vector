* Verified Facts

The imported Tek9 revision remains e6d1cb86a2e268a894eae3acae9617238b2adcff.
The new text library uses the existing Nim C ABI for storage/search. Python
reuses the encoder and store in process. Nim, Common Lisp and Node.js helpers
use the same local CLI commands; TypeScript declarations are checked. No
daemon or remote protocol was added.

The real provider is spaCy 3.8.16 with the official en_core_web_md 3.8.0 model,
300 dimensions. The downloaded 33,480,380-byte wheel has SHA256
5e6329fe3fecedb1d1a02c3ea2172ee0fede6cea6e4aefb6a02d832dba78a310.
The model tokenizer, config and vocabulary files have individual checked
SHA256 pins in =clients/python/star_vector_client/model.json=. The optional
Nix output fetches the fixed wheel; runtime performs no downloads. The local
proof used Python 3.12.14 and NumPy 2.5.4; complete dependency versions and
actual timings are in =benchmarks/results/text-2026-10-11/proof.json=.

The real-model test uses four synthetic prose documents and a separate
related query. It checks all four metric scores against independent scalar
calculations over the exact emitted float32 vectors. The related cat document
ranks first for the kitten query. This is an end-to-end semantic demonstration,
not a retrieval quality benchmark. A fresh encoder/store reopens the data.
Python creates a shared canonical document, Nim updates it, JavaScript updates
it again, Common Lisp updates it, and Python verifies final revision,
provenance and unrelated extensions. A real-model writer is killed with
SIGKILL after acknowledgement; a fresh handle verifies text/profile/vector
readback. Empty, oversized and all-unknown text are rejected without truncation.

Five separate deterministic fixture tests passed for all metrics, exact ties,

* Inference

The immutable profile prevents accidental mixing of incompatible model,
dimension, extraction, pooling and normalization versions through these APIs.
Profile-aware writes and binding share the producer write transaction. A
distinct v2 application header and ready state also fence old v1 workers.
This is compatibility enforcement, not authentication of arbitrary custom
encoders. Callers supplying their own profile must describe their encoder
accurately.

For repeated ingestion, the reusable Python library avoids per-call model
startup. The convenience clients favor a small shared interface and explicit
local boundary; they are not evidence of high-throughput remote serving.
The existing scale report and Tek9-authoritative tiered/history design remain
applicable; no ANN implementation or history API is introduced here.

* Unresolved Questions

Final-head native package behavior and independent review remain pending.
The static English encoder does not establish contextual, multilingual or
domain-specific retrieval quality. Large text chunking is explicit caller work;
the encoder rejects over 1,000,000 characters. Different recorded NumPy
versions yield different profiles. Convenience calls incur process/model
startup. Acknowledged-write process-kill tests are not device power-loss proof.
No billion-row text run, remote daemon, automatic revision history or
production-readiness claim is made.
